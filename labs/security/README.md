# Security Labs

## Objective

Apply security best practices in cloud-native environments by implementing identity, policy, and runtime controls in Kubernetes.

## Lab Structure

- `starter/` - Starter code and configuration for the lab
- `solution/` - Reference solution for the lab
- `tests/` - Test cases and validation scripts
- `scripts/` - Automation scripts for setup, run, verify, test, clean
- `artifacts/` - Output and evidence generated by lab activities

## Executable Workflow

```bash
# 1. Setup the lab environment
./scripts/setup.sh

# 2. Run the main workflow
./scripts/run.sh

# 3. Verify the lab state
./scripts/verify.sh

# 4. Run tests
./scripts/test.sh

# 5. Clean up the environment
./scripts/clean.sh
```

Each script is documented and must be run from the root of this lab directory.
## Prerequisites

- Understanding of Kubernetes fundamentals
- Access to a Kubernetes cluster (local or cloud)
- kubectl CLI installed and configured
- OPA Gatekeeper or Kyverno installed for policy enforcement
- (Optional) A secrets manager (e.g., HashiCorp Vault)

## Scenario

You are responsible for securing a Kubernetes-based application. Your tasks include enforcing least privilege, securing secrets, and implementing runtime policy controls.

## Steps

1. **Identity and Access**
   - Configure RBAC to restrict access to cluster resources.

2. **Secrets Management**
   - Store and mount secrets securely using Kubernetes Secrets or an external manager.

3. **Policy Enforcement**
   - Deploy OPA Gatekeeper or Kyverno to enforce security policies (e.g., block privileged containers).

4. **Network Segmentation**
   - Apply NetworkPolicies to isolate sensitive workloads.

5. **Runtime Controls**
   - Enable admission controllers or service mesh policies for runtime enforcement.

6. **Simulate Breach**
   - Attempt a policy violation (e.g., run a privileged pod) and verify enforcement.

## Validation

- RBAC and policies restrict access as intended.
- Secrets are not exposed in plaintext.
- Policy violations are detected and blocked.

## Common Failure Modes

- Overly broad RBAC permissions.
- Secrets accidentally committed to version control.
- Policy engine misconfiguration allowing insecure workloads.

## Cleanup

1. Remove test policies, secrets, and demo workloads.
2. Uninstall policy engines and secrets manager (if used).
