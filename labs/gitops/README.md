# GitOps Labs

## Objective

Learn the principles and practices of GitOps by managing Kubernetes deployments declaratively using version control and automated reconciliation.

## Lab Structure

- `starter/` - Starter code and configuration for the lab
- `solution/` - Reference solution for the lab
- `tests/` - Test cases and validation scripts
- `scripts/` - Automation scripts for setup, run, verify, test, clean
- `artifacts/` - Output and evidence generated by lab activities

## Executable Workflow

```bash
# 1. Setup the lab environment
./scripts/setup.sh

# 2. Run the main workflow
./scripts/run.sh

# 3. Verify the lab state
./scripts/verify.sh

# 4. Run tests
./scripts/test.sh

# 5. Clean up the environment
./scripts/clean.sh
```

Each script is documented and must be run from the root of this lab directory.
## Prerequisites

- Access to a Kubernetes cluster (local or cloud)
- kubectl CLI installed and configured
- Git installed and a GitHub account
- (Optional) [Flux](https://fluxcd.io/) or [Argo CD](https://argo-cd.readthedocs.io/) installed for GitOps automation

## Scenario

You are tasked with deploying and managing a Kubernetes application using GitOps principles. This lab will guide you through storing manifests in Git, configuring a GitOps tool, and observing automated reconciliation between Git and your cluster.

## Steps

1. **Fork or Clone a GitOps Example Repository**
   ```sh
   git clone https://github.com/fluxcd/flux2-kustomize-helm-example.git
   cd flux2-kustomize-helm-example
   ```

2. **Review the Repository Structure**
   - Explore the `clusters/` and `apps/` directories to understand how manifests are organized.

3. **Install a GitOps Tool (Flux Example)**
   - Follow [Flux installation guide](https://fluxcd.io/docs/installation/) for your environment.

4. **Bootstrap Flux to Your Cluster**
   - Replace `<GITHUB-USER>` and `<REPO>` with your GitHub username and repo:
     ```sh
     flux bootstrap github \
       --owner=<GITHUB-USER> \
       --repository=<REPO> \
       --branch=main \
       --path=./clusters/my-cluster
     ```

5. **Observe Automated Reconciliation**
   - Make a change to a manifest in your GitHub repo (e.g., update an image tag).
   - Commit and push the change.
   - Flux will detect the change and apply it to your cluster automatically.

6. **Validate the Deployment**
   ```sh
   kubectl get deployments -A
   ```

7. **(Optional) Try Argo CD**
   - Install Argo CD and follow its [getting started guide](https://argo-cd.readthedocs.io/en/stable/getting_started/).

## Validation

- Changes to manifests in Git are automatically applied to the cluster.
- `kubectl get deployments` shows the expected state.
- GitOps tool status commands (e.g., `flux get kustomizations`) show healthy sync.

## Common Failure Modes

- **Authentication errors:** Ensure your GitHub token and cluster credentials are correct.
- **Sync failures:** Check GitOps tool logs for errors and verify manifest syntax.
- **Network issues:** Ensure your cluster can reach GitHub and vice versa.

## Cleanup

- Uninstall the GitOps tool (see [Flux uninstall guide](https://fluxcd.io/docs/cmd/flux_uninstall/)).
- Delete the example repository:
  ```sh
  cd ..
  rm -rf flux2-kustomize-helm-example
  ```
