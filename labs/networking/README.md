# Networking Labs

## Objective

Develop practical skills in cloud-native networking, including service discovery, traffic management, and network policy enforcement in Kubernetes environments.

## Lab Structure

- `starter/` - Starter code and configuration for the lab
- `solution/` - Reference solution for the lab
- `tests/` - Test cases and validation scripts
- `scripts/` - Automation scripts for setup, run, verify, test, clean
- `artifacts/` - Output and evidence generated by lab activities

## Executable Workflow

```bash
# 1. Setup the lab environment
./scripts/setup.sh

# 2. Run the main workflow
./scripts/run.sh

# 3. Verify the lab state
./scripts/verify.sh

# 4. Run tests
./scripts/test.sh

# 5. Clean up the environment
./scripts/clean.sh
```

Each script is documented and must be run from the root of this lab directory.
## Prerequisites

- Familiarity with Kubernetes basics
- Access to a Kubernetes cluster (local or cloud)
- kubectl CLI installed and configured
- (Optional) Istio or Linkerd installed for service mesh exercises

## Scenario

You are tasked with deploying a multi-service application in Kubernetes. You must ensure reliable service-to-service communication, implement traffic policies, and observe network flows.

## Steps

1. **Deploy Multi-Service Application**
   - Launch a sample app with multiple communicating services (use a provided example or your own).

2. **Service Discovery**
   - Explore how Kubernetes DNS and Service objects enable discovery between services.

3. **Network Policies**
   - Apply Kubernetes NetworkPolicies to restrict traffic between pods.

4. **Traffic Management (Optional)**
   - Use a service mesh (Istio/Linkerd) to implement traffic splitting, retries, and circuit breaking.

5. **Monitor Network Flows**
   - Use tools like `kubectl`, Cilium, or service mesh observability features to inspect traffic and enforce policies.

6. **Simulate Network Failure**
   - Block traffic between services and observe application impact.

## Validation

- Services communicate only as allowed by policies.
- Traffic management features (if used) work as expected.
- Network failures are detected and diagnosed.

## Common Failure Modes

- Overly permissive or restrictive network policies.
- DNS misconfiguration breaking service discovery.
- Service mesh misconfiguration causing traffic loss.

## Cleanup

1. Remove the sample application and any installed networking tools.
2. Delete custom network policies.
