# Observability Labs

## Objective

Develop practical skills in observability by instrumenting applications for metrics, logs, and traces, and visualizing them using open-source tools.

## Lab Structure

- `starter/` - Starter code and configuration for the lab
- `solution/` - Reference solution for the lab
- `tests/` - Test cases and validation scripts
- `scripts/` - Automation scripts for setup, run, verify, test, clean
- `artifacts/` - Output and evidence generated by lab activities

## Executable Workflow

```bash
# 1. Setup the lab environment
./scripts/setup.sh

# 2. Run the main workflow
./scripts/run.sh

# 3. Verify the lab state
./scripts/verify.sh

# 4. Run tests
./scripts/test.sh

# 5. Clean up the environment
./scripts/clean.sh
```

Each script is documented and must be run from the root of this lab directory.
## Prerequisites

- Docker installed
- Basic command-line proficiency
- (Optional) Kubernetes cluster for advanced exercises

## Scenario

You are tasked with adding observability to a sample application. This lab will guide you through collecting metrics, logs, and traces using open-source tools (Prometheus, Grafana, and Jaeger) in a local Docker environment.

## Steps

1. **Clone the Example Application**
   ```sh
   git clone https://github.com/GoogleCloudPlatform/microservices-demo.git
   cd microservices-demo
   ```

2. **Start Observability Stack with Docker Compose**
   - Use the provided `docker-compose-observability.yaml` (or create your own) to launch Prometheus, Grafana, and Jaeger:
     ```sh
     docker compose -f ./release/docker-compose/docker-compose.yaml up -d
     ```

3. **Instrument the Application**
   - Review the sample app's code for metrics, logging, and tracing instrumentation.
   - (Optional) Add a custom log or metric to one of the services.

4. **Access Observability Dashboards**
   - Prometheus: [http://localhost:9090](http://localhost:9090)
   - Grafana: [http://localhost:3000](http://localhost:3000) (default login: admin/admin)
   - Jaeger: [http://localhost:16686](http://localhost:16686)

5. **Generate Traffic**
   - Use the app's frontend or a load generator to create sample requests.

6. **Explore Metrics, Logs, and Traces**
   - Query metrics in Prometheus.
   - Visualize dashboards in Grafana.
   - Trace requests in Jaeger.

7. **(Optional) Deploy to Kubernetes**
   - Follow the repo's Kubernetes deployment guide for a more advanced scenario.

## Validation

- Prometheus, Grafana, and Jaeger dashboards are accessible.
- Metrics, logs, and traces are visible and update as traffic is generated.
- Custom instrumentation (if added) appears in the dashboards.

## Common Failure Modes

- **Port conflicts:** Ensure required ports (9090, 3000, 16686) are available.
- **Service startup errors:** Check Docker Compose logs for issues.
- **No data in dashboards:** Verify the app is running and generating traffic.

## Cleanup

- Stop and remove containers:
  ```sh
  docker compose -f ./release/docker-compose/docker-compose.yaml down
  ```
- Remove the cloned repository:
  ```sh
  cd ..
  rm -rf microservices-demo
  ```
